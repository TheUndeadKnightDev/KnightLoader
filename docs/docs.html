Documentation

KnightLoader docs

Everything you need to install KnightLoader and build mods with it. Applies to KnightLoader v1.x on Unity Mono games (IL2CPP titles are not supported).

Installing

  1. Download the latest KnightLoader-vX.Y.Z.zip from the Releases section.
  2. Copy everything in the zip into your game's folder — the one containing the game's .exe (for Raft: ...\steamapps\common\Raft).
  3. Launch the game normally (Steam is fine).
  4. Confirm it's running: the file KnightLoader\KnightLoader.log appears in the game folder and ends with N mod(s) active.

Your game folder will look like this:

Raft\
  Raft.exe
  winhttp.dll              ← Doorstop bootstrap (loads KnightLoader at startup)
  doorstop_config.ini
  .doorstop_version
  KnightLoader\
    KnightLoader.dll        ← the loader
    0Harmony.dll            ← runtime patching library
    Mono.Cecil.dll
    KnightLoader.log        ← created on first launch
  Mods\
    SampleMod.dll           ← mods go here (one DLL each)

No game files are modified. To disable temporarily, rename winhttp.dll to winhttp.dll.disabled.

Your first mod

A mod is a single .NET class-library DLL dropped into Mods\. You need any C# compiler (Visual Studio, Rider, or the dotnet SDK) and three kinds of references, all taken from your KnightLoader install and your game:

  • KnightLoader\KnightLoader.dll — the mod API
  • KnightLoader\0Harmony.dll — only if you patch game code
  • Game assemblies from <Game>_Data\Managed\ — e.g. UnityEngine.CoreModule.dll, and Assembly-CSharp.dll for the game's own classes

Minimal project file (MyFirstMod.csproj):

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>netstandard2.0</TargetFramework>
    <AssemblyName>MyFirstMod</AssemblyName>
  </PropertyGroup>
  <ItemGroup>
    <Reference Include="KnightLoader">
      <HintPath>C:\...\Raft\KnightLoader\KnightLoader.dll</HintPath>
    </Reference>
    <Reference Include="0Harmony">
      <HintPath>C:\...\Raft\KnightLoader\0Harmony.dll</HintPath>
    </Reference>
    <Reference Include="UnityEngine.CoreModule">
      <HintPath>C:\...\Raft\Raft_Data\Managed\UnityEngine.CoreModule.dll</HintPath>
    </Reference>
  </ItemGroup>
</Project>

And the mod itself (MyFirstMod.cs):

using KnightLoader;

[ModInfo("My First Mod", "1.0.0", "YourName")]
public class MyFirstMod : Mod
{
    public override void OnLoad()
    {
        LogInfo("Hello from My First Mod!");
    }
}

Build with dotnet build -c Release, copy MyFirstMod.dll into Mods\, launch the game, and check KnightLoader.log for your hello.

The mod lifecycle

The loader scans Mods\*.dll at startup, instantiates every class implementing IMod, then drives these callbacks on Unity's main thread. Exceptions in any callback are caught and logged per-mod — one broken mod can't take the others down.

CallbackWhen it runsUse it for
OnLoad()Once, after all mods are discoveredSetup, applying Harmony patches
OnUpdate()Every frame (Unity Update)Input polling, per-frame logic — keep it light
OnGUI()Unity's IMGUI pass (multiple times per frame)Overlays, debug UI
OnUnload()Once, on game quitUnpatching, saving, cleanup

API reference

abstract class Mod : IMod

The recommended base class — override only what you need.

MemberDescription
HarmonyHarmonyLib.Harmony instance unique to this mod, created on first access. Use it to apply and remove your patches.
LogInfo / LogWarn / LogError(string)Write to KnightLoader.log, prefixed with your mod's class name.
OnLoad / OnUpdate / OnGUI / OnUnload()Lifecycle overrides (see above). All optional.

[ModInfo(name, version, author)]

Optional class attribute giving your mod a friendly display name in the log. version defaults to "1.0.0", author to empty.

interface IMod

The raw contract (OnLoad, OnUpdate, OnGUI, OnUnload) — implement it directly if you don't want the base class conveniences.

Patching game code

KnightLoader ships Harmony 2 for rewriting game methods in memory at runtime. Decompile the game's Assembly-CSharp.dll with ILSpy or dnSpy to find targets, then declare patches and apply them in OnLoad. A real example from the Raft SampleMod — cancelling all player damage:

using HarmonyLib;
using KnightLoader;

[ModInfo("God Mode", "1.0.0")]
public class GodMode : Mod
{
    internal static bool Enabled = true;

    public override void OnLoad()
    {
        Harmony.PatchAll();      // applies every [HarmonyPatch] in this DLL
        LogInfo("Patched.");
    }

    public override void OnUnload()
    {
        Harmony.UnpatchAll(Harmony.Id);
    }
}

// PlayerStats.Damage is a real method in Raft's Assembly-CSharp.dll.
// A prefix returning false skips the original entirely.
[HarmonyPatch(typeof(PlayerStats), nameof(PlayerStats.Damage))]
static class Patch_Damage
{
    static bool Prefix() => !GodMode.Enabled;
}

Prefix runs before the original (return false to skip it), Postfix after it, Transpiler rewrites its IL. See the Harmony documentation for the full patching guide.

Other Unity games

The loader core contains no Raft-specific code. To use it with another Unity Mono game, copy the same four items (winhttp.dll, doorstop_config.ini, .doorstop_version, KnightLoader\) into that game's folder and create a Mods\ folder. A game is Mono if its install has a MonoBleedingEdge folder; if it has GameAssembly.dll instead, it's IL2CPP and not supported.

Troubleshooting

SymptomFix
No KnightLoader.log appearsDoorstop didn't load: check winhttp.dll and doorstop_config.ini are next to the game's .exe, and enabled=true in the ini.
Log says No IMod implementation foundYour mod class must be public, non-abstract, and implement IMod (or extend Mod).
Failed to load <mod>.dllUsually a missing reference — ship extra dependency DLLs in Mods\ (the loader resolves from there), and build against the game's own assembly versions.
Legacy Input throwsSome games (incl. Raft) use the new Input System; wrap legacy input in try/catch or use UnityEngine.InputSystem.
Game misbehaves with mods installedRename winhttp.dll → winhttp.dll.disabled to confirm it's mod-related, then remove mod DLLs one at a time.

Uninstalling

Delete winhttp.dll, doorstop_config.ini, .doorstop_version, the KnightLoader\ folder and the Mods\ folder from the game directory. That's everything — no game files were ever changed.
